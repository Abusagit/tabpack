# Личное рабочее пространство veleboks

- В `dev/veleboks/` не создавайте и не ведите README. Локальные правила для агентов храните в этом личном `AGENTS.md`.
- Обращайтесь к Notion только в начале задачи для чтения контекста и в конце задачи для итоговой записи. Не читайте и не обновляйте Notion на каждом промежуточном шаге или после каждого seed.
- Замечания к экспериментам, интерпретацию результатов, ограничения замеров, выводы и решения сохраняйте одной итоговой записью в существующую запись проекта в Notion. Не используйте README и отдельные Markdown-отчёты в этой папке для таких записей.
- Текущая запись проекта в Notion: https://app.notion.com/p/414b2e5eb426810eaa3dd13a1987ce03. В конце задачи перечитайте её перед итоговым редактированием и обновите существующую запись вместо создания дубликатов.
- Скрипты, конфиги и машинно-читаемые результаты остаются в репозитории; большие датасеты, трассы, чекпоинты и полные пакеты запусков — в игнорируемом `artifacts/`.
- В записях Notion указывайте run ID, конфигурацию, оборудование, версии окружения, ссылки на источники и ограничения сравнения. Отделяйте результаты завершённых запусков от предположений и незавершённых замеров.
- Если запись в Notion недоступна, покажите несохранённые замечания в чате и явно сообщите, что они не сохранены. Не создавайте вместо этого README.
- Соблюдайте корневой `AGENTS.md`: локальный worktree — источник истины для кода, каждый удалённый запуск получает отдельный неизменяемый снимок, коммит и push требуют запроса пользователя.
